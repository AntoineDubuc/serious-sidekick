# The Architect — Round 5

## Closing the Three Questions Through the Lens of Long-Term Design

**1. `[VERIFIED: manual override]` — build now.** This isn't a convenience feature; it's a structural requirement. Without it, you have no escape hatch between "verifier is wrong" and "re-run the entire skill." That's a broken interface. The implementation is trivial — a marker the verifier recognizes on subsequent runs to skip that item. Build it as part of the verifier prompt itself: "If an item is annotated `[VERIFIED: manual override]`, treat it as covered." Zero additional tooling. One line in the prompt. No reason to defer.

**2. Omissions only for v1. No contradiction detection.** Contradiction detection is a fundamentally different operation — it requires understanding *what* the downstream artifact says about each item, not just *whether* it says something. That's a semantic depth increase that doubles verifier complexity and halves its reliability. Omission detection is binary: present or absent. Ship the binary check. If contradictions become a pattern users report, the architecture supports adding a second pass later without modifying the omission check. Clean separation of concerns.

**3. Handoff verifier and serious-code's completion gate: complementary layers at different boundaries.** The handoff verifier checks *inter-skill* traceability — did the downstream skill account for everything upstream produced? The completion gate checks *intra-skill* completeness — did serious-code finish everything in the plan? Different boundaries, different responsibilities, zero overlap. Think of it as: the verifier guards the front door (did you receive the full delivery?), the completion gate guards the back door (did you use everything you received?). They should reference the same artifact but run independently.

**Remaining architectural risk:** The verifier runs *after* the downstream skill writes its output. If the skill took 20 minutes, a FAIL verdict means 20 minutes of work gets revisited. Phase 0-pre already validates preconditions at startup — consider having the verifier also run a quick "upstream artifact is well-formed and extractable" check at startup, before the skill burns time. Cheap insurance.
