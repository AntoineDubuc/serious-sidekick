Prompts are suggestions.
Gates are law.

Telling the AI to verify is asking the contractor if they passed inspection. Serious Sidekick is the building inspector — bash scripts running outside the AI's process.

The AI says it's done. A 50-line bash script checks if gate_passed.md exists. It doesn't. Session stays open. The AI can't argue — it fixes the work.

How precise? When the AI writes a verdict file, only the review-theater gate fires — not the TDD gate, not the completion gate. Each hook declares its trigger: if: "Write(*verdict*)". Binary: pass or block.

settings.json
{ "hooks": { "PreToolUse": [{ "matcher": "Write", "hooks": [{ "type": "command", "if": "Write(*gate_passed*)", "command": "verify-completion-gate.sh" }] }] } }
Hook Output
── Hook: verify-completion-gate ─────────── Trigger: Write(*gate_passed*) ✓ All tests pass ✓ Plan tasks complete ✓ No skipped phases ✓ gate_passed.md written PASS — session can close
Deterministic, not probabilistic. Hooks are bash scripts. They check if files exist, grep for required content, count citations. No AI reasoning in the verification loop — it either passes or it doesn't.
Outside the AI's process. The Claude Code runtime executes hooks after the AI responds. The AI cannot disable, skip, or override them.
Fail-closed. If a hook hits an unexpected error, it blocks instead of silently passing. No silent failures. No false confidence.
Surgical, not blunt. Hooks declare exactly which tool calls they care about. Write(*verdict*) fires the review gate. Write(*.ts) fires the TDD gate. Write(*implementation_plan*) fires the hedge language check. No wasted process spawning. No false positives.

Most Claude Code toolkits verify with prompts. We verify with bash.

That's not a style choice — it's a structural one. Prompts live inside the AI's reasoning loop. Bash lives outside it. One can be rationalized. The other can't.

Hooks verify that verification ran. You still trust the AI to do the work. You don't trust it to grade itself.

Every hook is a shell script you can read. No magic. No hidden AI. Open the file and see exactly what it checks.

What just happened: One command updated skills, agents, hooks, and settings.json across all your Claude profiles. Your custom hooks survived. Your plugins survived. Your status line survived. Only serious-owned components were touched.

Manifest-driven. A JSON manifest tracks every file with ownership tiers and content hashes. Template files get overwritten. Your settings.json gets a surgical composite-key merge. Your CLAUDE.md is never touched.
Settings-safe. The merge engine knows the difference between your hooks and ours. It replaces serious-owned entries, appends new ones, and preserves everything else — including non-hook keys like statusLine and enabledPlugins.
Always aware. A daily background check tells you when you're behind. Next time you open Claude Code: "4 components behind. Run serious-update." No network call in your session — just a cached flag.
Rollback in seconds. serious-update --rollback reverts to the previous version across all directories. Every update is logged with commit SHAs and file counts.
