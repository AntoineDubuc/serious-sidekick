Getting Started

Quick Start

Three steps to install Serious Sidekick in any project.

1

Clone the template repo

This is where all the skills, docs, and templates live. You only need to do this once per machine.

$git clone https://github.com/AntoineDubuc/serious-sidekick.git
2

Copy the global skills

Copy the workflow skills into your Claude Code global profile so they're available in every project.

$mkdir -p ~/.claude/skills
$cp -r serious-sidekick/.claude/skills/* ~/.claude/skills/
3

Set up any project

Open Claude Code in your project and type:

>/serious-init

This copies all skills, hooks, docs, and templates into your project. Run it again anytime to update.

Pipeline Integrity

Automatic Handoff Verification

Every arrow in the pipeline above is guarded. An independent verifier fires at each handoff to check that nothing was dropped, deferred, or half-done. No commands, no flags — it just happens.

1

Extract

An independent sub-agent reads the upstream artifact and pulls out every enumerable item — findings, decisions, requirements, criteria.

2

Check

For each item, the verifier checks whether the downstream output actually addresses it — not just mentions it, but gives it real substance.

3

Classify

Each item gets one of 6 dispositions: Covered, Deferred (max 3), Shirked, Missing, Contradicted, or Override.

4

Block

Any shirked or missing items = FAIL. The skill loops and fixes before proceeding. Drift is caught at the handoff, not at the end.

11 shirking patterns detected

6 general: "future enhancement," hollow sections with headings but no content, vague hand-waves, scope deferral to v2...
5 LLM-specific: "configurable policy layer," "this should be abstracted," confidence-sounding non-answers...

Max 3 deferrals per artifact — more requires explicit approval
💡
Retroactive verification. Artifacts created before the verifier existed get caught the moment someone tries to use them. The system checks for a verification stamp in the frontmatter — if it's missing, verification runs before proceeding.
Enforcement

Stop Hooks — The System Checks Itself

Three shell scripts fire every time a Claude session ends. They catch incomplete work before it's forgotten. You don't run them — they run automatically.

Completion Gate

If you're mid-/serious-code and try to exit, the hook checks every task's evidence directory for gate_passed.md. Missing one? Session blocked. You must run the Completion Gate verification before leaving.

Conversation Capture

If you're in a /serious-conversation and try to exit without wrapping up, the hook warns that no summary.md exists. Your conversation insights won't survive to the next session without it.

Research Capture

If you're in a /serious-research and try to exit before it's finalized, the hook checks the frontmatter status. Still "active"? You'll be warned that findings are incomplete.

💡
How it works: These hooks are registered in .claude/settings.json and installed automatically by /serious-init. They run outside Claude's control — the AI cannot skip or override them. If a hook blocks exit, the only way out is to complete the work or abandon the workflow.

Brainstorm with AI Personas

/serious-conversation

Think of this as a roundtable discussion. You describe a topic, and Claude creates a panel of fictional experts who each give their perspective. You read their ideas, respond, and they refine. It's brainstorming, but structured.

When to use it

  • You have a vague idea and want to explore it
  • You want to see different perspectives
  • You're stuck and need creative input
  • You want to think through trade-offs

What you get

  • Multiple expert viewpoints per round
  • A synthesis that merges the best ideas
  • Versioned artifacts in your project
  • A record you can hand off to other skills
How it works
1

Describe what you want to explore

Example: "I want to add push notifications but I'm not sure about the approach."

2

Personas weigh in independently

Each persona responds via a sub-agent. The Orchestrator reads all responses and writes a synthesis.

3

You respond and they refine

Say what resonated, what you disagree with, or ask a follow-up. Do as many rounds as you need.

4

Everything is saved

Output goes to Research/conversations/. Feed it into /serious-research or /serious-plan.

The Skeptic

The Debugger

The Security Mind

The DX Advocate

The Mentor

The Optimizer

Investigate Before You Build

/serious-research

Before writing any code, understand the problem. This skill reads your codebase, finds the relevant files, traces how things connect, and writes up findings with evidence. Think of it as hiring a detective for your codebase.

When to use it

  • A bug you can't figure out
  • You want to add a feature but don't know what it touches
  • You need to understand something before changing it
  • You want documented findings, not just a chat answer

What you get

  • A research.md file with structured findings
  • Root cause analysis (for bugs)
  • List of affected files and components
  • Recommended fix or approach
Two modes
Quick Mode

Focused Investigation

  • Single-threaded research
  • Persona reviews
  • Markdown deliverable

Best for: bug diagnosis, focused questions

Deep Mode

Comprehensive Analysis

  • Parallel thread agents
  • Evidence grading (A-F)
  • Adversarial verification
  • HTML report

Best for: architecture decisions, complex issues

How to use it
1

Describe the problem or question

Example: "Users are getting logged out randomly after about 30 minutes."

2

Choose quick or deep, and research scope

Scope can be online only, codebase only, or both — so agents only use the tools that matter.

3

Claude investigates

It searches files, traces function calls, reads config, and pieces together what's happening.

4

You get a research report

Saved to Research/bugs/, Research/features/, or Research/exploratory/. Feeds directly into /serious-plan.

💡
When in doubt, use quick mode. It's fast and covers most cases. Save deep mode for complex or critical issues.

Define Plan Boundaries

/serious-scope

Before writing a detailed plan, define how the work splits up. This skill reads your research, identifies natural boundaries, and proposes how many plans you need — each with its own scope, dependencies, and tags.

When to use it

  • Complex features that touch multiple systems
  • Multi-component work with unclear boundaries
  • You're not sure if this is one plan or three

What you get

  • A scope manifest with plan boundaries
  • Rationale for each split
  • Dependency map between plans
  • Tags for each plan (auth, infra, UI, etc.)
How it works
1

Claude reads your research

Auto-detects completed research, or you point it to a specific research.md.

2

Proposes a split with rationale

Groups by concern, checks coupling, and explains why each plan is separate. Tightly coupled items stay together; independent items split.

3

You approve or adjust

Merge plans, split further, edit rationale or tags. Nothing is written until you say go.

4

Manifest feeds into /serious-plan

Each plan entry in the manifest becomes a separate /serious-plan invocation with pre-defined boundaries.

💡
Under 100 lines. It's a lens, not an engine. Scope reads research and proposes structure — no persona pipeline, no quality validation. That's what /serious-plan and /serious-review are for.

Create the Implementation Plan

/serious-plan

Your idea becomes a step-by-step action plan. Claude takes your research (or description) and generates tasks with acceptance criteria, tests to write, and verification steps. Handoff verification ensures the plan covers every research finding.

1

Claude finds your research (or asks for input)

If you did /serious-research first, it's auto-detected. You can also point it to a document or just describe what to build.

2

Claude generates the plan

3-7 numbered tasks, each with acceptance criteria, risk levels, rollback plans, and TDD instructions.

3

Claude verifies coverage against research

The handoff verifier checks that every finding and recommendation from research appears in the plan. Any gaps are fixed before you see it.

4

You approve the plan, then run /serious-review

Review it, ask questions, request changes. Once approved, run /serious-review for adversarial quality checks before /serious-code.

What a plan looks like (simplified)

Task 0: Smoke test — reproduce the logout bug in the running app.

Task 1: Fix token refresh logic. Acceptance: token refreshes 5 min before expiry.

Task 2: Add retry logic for failed refreshes. Acceptance: 3 retries with backoff.

Task 3: Final smoke test — user stays logged in for 2+ hours.

⚠️
Big projects get split. Use /serious-scope first to split big projects into multiple plans. Each plan gets its own boundaries, dependencies, and tags.

🔎

Adversarial Plan Review

/serious-review

Before code gets written, the plan passes through an adversarial review gate. Three mandatory AI agents read your plan cold — no research context, no author notes — and surface structural defects, security gaps, and vagueness.

3 mandatory review agents

Anti-Slop Auditor

10 checks: vague language, copy-paste echo, phantom architecture, hollow tasks, missing error paths, and more

Structural Reviewer

Task dependencies, acceptance criteria quality, scope coverage, missing rollback plans, circular references

Security Mind

Auth flows, data exposure, injection surfaces, secret handling, privilege escalation, supply chain risks

Conditional agents

Data Privacy

Triggered by user-data, pii, or gdpr tags. Checks data classification, retention, and consent.

Infrastructure

Triggered by infrastructure or infra tags. Checks resource limits, deployment config, scaling, and rollback.

How it works
1

Cold read

Agents read only the plan — no research, no conversation history, no author notes. If the plan can't stand on its own, that's a finding.

2

Independent agent reports

All 3 mandatory agents run in parallel. Each produces a structured report with per-check verdicts and an overall assessment.

3

Verdict synthesis

PASS, PASS-WITH-CONDITIONS, or FAIL. Any Critical finding = automatic FAIL. 3+ Major findings across agents = FAIL. Circuit breaker: max 2 rounds.

4

You decide on FAIL

Options: fix the issues and re-run review, override with a documented reason, or re-scope with /serious-plan. The review gate does not auto-fix.

💡
Structural separation. The reviewing agent has no memory of the planning conversation. /serious-review must be a separate invocation from /serious-plan — this is by design, not a limitation.

Execute the Plan

/serious-code

This is where code gets written. Claude reads your plan and works through each task: writes a failing test first, writes the code to make it pass, then 5 separate AI agents verify. The agents are hardened against the same LLM failure modes they're meant to catch — each has anti-rationalization tables and the Reviewer and QA run with anti-sycophancy rules. Nothing gets marked "done" unless all checks pass.

The execution cycle per task
Smoke
→
Stub Check
→
Red (test)
→
Green (code)
→
Verify (5 agents)
→
Smoke
The 5 verification agents

Implementer

Strict TDD with anti-rationalization table (8 excuses for skipping tests, each debunked)

Code Reviewer

Two-stage review: spec compliance first (COMPLIANT/PARTIAL/MISSING/WRONG), then code quality. Anti-sycophancy + anti-rationalization (7 excuses)

Test Runner

Static analysis + full test suite

Runtime Checker

Does it work in the actual app?

QA Spot-Checker

Adversarial re-verification of 3+ random criteria. Anti-sycophancy + anti-rationalization (6 excuses). "If you find no problems, be suspicious of yourself."

1

Claude finds your plan and shows a summary

Task count, risk levels, what's about to happen. Say "Go" to start.

2

Tasks execute sequentially with full verification

Each task: smoke test → stub check → TDD → 5 agents verify → Completion Gate confirms all ACs have reachable code.

3

If anything fails, it stops

Options: fix and resume, skip, roll back, or abort. Nothing is silently skipped.

4

Completion report with evidence

Every task gets an evidence folder (implementation, review, tests, runtime, QA). A completion_report.md summarizes everything.

Evidence structure

evidence/
  task_01/
    implementation.md, review.md, tests.md, runtime.md, qa.md
    gate_passed.md ← proof it's done
  task_02/ ...
completion_report.md
💡
You can walk away. Once you say "Go", Claude works through tasks on its own. Use /serious-code --resume to pick up where it left off in a new session.
Utility Skills

The supporting cast

Not part of the main pipeline, but you'll use them regularly.

/serious-init

Set up a new project. Copies all skills, hooks, docs, and templates. Run it again anytime to update to the latest version.

/serious-status

See all workflows in a tree view — active, done, abandoned. Shows parent-child relationships for nested workflows.

/serious-abandon

Bail out of a sub-workflow cleanly. Sets status to "abandoned", restores the parent context. Nothing is deleted.

/serious-bananas

Nano Banana 2 image generation via Gemini (gemini-3.1-flash-image-preview). 4K resolution, dark mode, 14 aspect ratios, reference images, iterative editing. Three model tiers: NB2 (default), Pro (complex), v1 (budget). Requires GEMINI_API_KEY in .env.

★ Headline Feature

Recursive Workflows

The pipeline is linear. Real work isn't. When you discover a sub-problem mid-plan, you can branch into a child workflow and come back when it's done — without losing your place.

Linear vs. Recursive Pipeline

/serious-status

See every workflow — parents, children, active, done, abandoned — in one tree.

/serious-abandon

Dead end? Bail out. Parent context is restored. Nothing deleted — work stays for reference.

Architecture

Three knowledge layers

Each loads at a different time to save context window space.

CLAUDE.md Always loaded
Feature index + mandatory rules. Claude always knows what exists and where to find details.
29 Skills On demand
Correct syntax, config, and patterns. Auto-loads when the topic comes up. Prevents hallucinated details.
39 Research Docs When needed
Full references with official doc excerpts, all config options, and source URLs. Only loaded when explicitly read.
💡
Why this matters: Claude hallucinates feature details from training data. These layers inject correct syntax, flags, and patterns exactly when needed.

FAQ

Common questions

?

Do I have to use skills in order?

No. Each skill works on its own. Jump to whichever one matches where you are right now.

?

What if I need to go back a step?

That's what sub-workflows are for. Type the earlier skill — Claude asks if you want to link it as a child. When it's done, you pick up where you left off.

?

Where does everything get saved?

All output goes in a Research/ folder, organized by type. Everything is plain Markdown — readable in any text editor.

?

Can I use this on any project?

Yes. Run /serious-init in any project. Works with any language and framework. The skills guide Claude, which adapts to your stack.

?

What if something fails during /serious-code?

Claude stops and asks you. Options: fix and resume, skip, roll back, or abort. Use --resume to continue in a new session.

?

How is this different from just asking Claude to code?

Without Serious Sidekick: Claude writes code, says "done", no verification. With it: research first, plans reviewed by personas, code verified by 5 agents, evidence that proves each piece works. "I think it works" vs "here's proof."

?

How do I keep it updated?

Pull the latest from the template repo and run /serious-init again in your projects. It overwrites skills and docs with the latest versions.

💡
First time? Open Claude Code in any project, type /serious-research, and describe something you've been curious about in your codebase. That's the best way to get started.
